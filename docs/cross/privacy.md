# 隐私与凭据防护

## 事实陈述

**代码内容会发送到第三方 API。**

| 环节 | 是否联网 | 发送内容 |
|---|---|---|
| 嵌入 | 是 | 代码片段全文 |
| 重排 | 是 | 候选片段全文 + 查询 |
| 提交摘要 | 是 | diff（截断后） |
| 符号关系 | **否** | language server 本地运行 |
| 存储与检索 | **否** | 全部本地 |

这一点必须写在 README 第一屏，不能藏在文档深处。很多人选择自部署索引器正是为了避免代码外传，如果这个工具做不到，要让他们在安装前就知道。

## 强制防护一：路径过滤

以下路径默认不索引、不发送：

```
.env
.env.*
*.pem
*.key
id_rsa
id_rsa.*
credentials
credentials.*
secrets/
```

用户可以覆盖这个列表，但必须显式配置。默认值偏保守。

## 强制防护二：发送前凭据扫描

在任何内容离开本机之前扫描常见凭据形态：

- AWS access key（`AKIA` 前缀）
- GitHub token（`ghp_` / `gho_` / `ghs_` 等前缀）
- 私钥 PEM 头（`-----BEGIN ... PRIVATE KEY-----`）
- 通用高熵字符串启发式

命中则跳过该片段并记录告警，不阻断整个索引流程。

### 为什么这不是可选项

仓库里硬编码的密钥被成批发送到第三方 API——这不是假想威胁，是真实的事故形态。一次全量索引会把仓库历史上所有被提交过的凭据都扫一遍。

提交历史尤其危险：一个早已被修复的密钥泄露，在 git 历史里仍然存在，而提交摘要管线会读到它。

## 数据留存

各家的留存政策和零留存选项不同，实现时逐个核实并列入文档。

工具的责任是**把选择权和足够的信息交给用户**，不是替用户判断哪家可信。

## 团队模式下的可见性

不做多租户隔离（`../00-decisions.md` D11）。团队共享同一份索引，**所有人可以检索到全部内容**。

如果仓库内部有分权要求（某些目录只对部分人可见），本工具不满足这个需求。这是明确的设计取舍，需要在文档中声明。

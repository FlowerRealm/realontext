# `parse/` 解析

语法层处理。纯函数——不调模型，不访问存储，不做网络请求。

**依赖**：tree-sitter。不依赖任何其他模块。
**被依赖**：`store/`（切块）、`curate/`（签名提取）

## 切块

函数 / 类粒度，深度优先遍历 AST。Chunk 之间**不重叠**，合起来覆盖文件的每一行：

| 语法结构 | 切法 | `symbol_path` |
|---|---|---|
| 函数、方法 | 一个 Chunk | `Outer::inner` |
| 类、结构体、impl 等容器 | 每个方法各自成块；容器剩余部分（声明、字段、非函数成员）合成一块 | 容器名 |
| 定义之外的顶层代码 | 相邻的兄弟节点合并成一块 | 空 |
| 没有 grammar 的文件 | 整个文件一块 | 空 |

**不按固定行数硬切**——那会把函数腰斩，嵌入出来的向量语义混乱。

`symbol_path` 按 `../benchmark.md` 的限定名归一化规则产出：去泛型与参数、receiver 归一到类型名、嵌套一律 `::`。

```
chunk_hash = blake3(content + language + symbol_path)
```

内容相同位置不同也复用：同一函数在两个分支里行号变了而内容没变，`store/` 不会重新嵌入。

### 目标尺寸未定

嵌入窗口 32K，但把 32K 塞进一个 Chunk 显然错。需要实验，且与 `curate/` 的保真分档相互影响。

见 [`../open-questions.md`](../open-questions.md) C6。

## 符号提取

从语法树提取每个 Chunk 定义和引用的符号名。

这些符号名交给 `lsp/` 做精确的关系查询。**本模块不解析跨文件作用域**——同名符号会串，那是 language server 的职责。

### 兜底档

没有可用 language server 时，`match/` 退化到用本模块的符号名做匹配。精度低（跨文件同名会串），但零配置、零外部依赖。

**只做两档：精确（LSP）和兜底（符号名）。** 不做中间态，中间态只会在代码里长出分支。

## 签名提取

供 `curate/` 的多级保真使用：

```
全文    完整代码                     数百至数千 token
签名    函数签名 + 文档注释           20–60 token
引用    path:line                    5–10 token
```

**签名档和引用档由本模块直接产出**：确定性、零成本、零延迟。

在查询路径上调模型做压缩，要为每次检索付钱和付延迟，方向错误。摘要档不由本模块产出，它只用于已有离线摘要的对象（提交记录、Playbook 条目）。

## 语言覆盖

tree-sitter 的 grammar 生态决定覆盖面。新增语言等于加一个 grammar，不改本模块逻辑。
